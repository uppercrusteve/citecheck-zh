# 检查方法与判定边界

本文说明 citecheck-zh 0.1.0 如何解析稿件、如何定位问题、10 条规则的精确判据、重排算法，以及哪些情况会误报或漏报。所有阈值均为固定值，不做机器学习，也不访问网络。

## 1. 目的与范围

citecheck-zh 是投稿前的**结构核对器**，不是文献管理器，也不是引文格式校验器。它回答的问题只有：

- 正文里的引用在文献表中是否存在；
- 文献表里的条目是否在正文出现过；
- 编号是否连续、是否按首次出现排序、是否越界；
- 是否存在重复条目、缺年份条目、坏 DOI；
- 引用所在部分是否有参考文献区、单处引用是否过长。

它不判断文献是否真实存在、作者顺序是否正确、期刊名是否缩写规范，也不判断是否符合 GB/T 7714—2015、ISO 690 或 APA 第 7 版。格式合规仍需人工或专门的 CSL 处理器。

## 2. 解析与定位

输入按 UTF-8（允许 BOM）读取，按行保留原始文本，行号从 1 开始。

**参考文献区。** 只识别独占一行的标题：Markdown 标题 `#`–`######`，或没有 `#` 的纯文本行；标题必须是 `参考文献`、`引用文献`、`References`、`Bibliography`、`Literature Cited`、`Works Cited` 之一，可带结尾冒号，英文不区分大小写。`## 参考文献与注释` 这类复合标题不会被识别。纯文本标题会把其后的全文都当作文献区。文献区在下一个同级或更高级 Markdown 标题处结束；无 `#` 标题没有层级，延伸到文件末尾。

**条目切分。** 位于文献区内的行才作为条目。`[1]`、`［1］`、`1.`、`1)`、`1、` 是编号标记，`-`、`*`、`+` 是列表标记；每个标记开始一条新条目，空行也会结束当前条目。编号条目之后的非空行并入同一条目；无编号的紧凑列表若没有空行分隔，会被并成一条。条目文本用于抽取年份、DOI、作者和标题，多行条目合并为一行。

**正文扫描。** 文献区之外的行才扫描引用；围栏代码块（以 ` ``` ` 开头的行之间）完全跳过。行内列号指向引用起始的方括号或圆括号，从 1 开始。

**部分划分。** C08 用一级标题（`# `）把稿件切块。文献区标题所在的块视为“有文献区”，其他块中的引用会触发 C08。没有一级标题时全文属于同一块。

**无文献区时。** 只运行不依赖文献表内容的规则：C04、C06、C08、C09、C10；C01、C02、C03、C05、C07 跳过。

## 3. 归一化

比较之前的文本归一化分三层：

1. `unicodedata.normalize("NFKC", text)`：全角转半角，兼容字符折叠（例如 `［`→`[`、`，`→`,`、全角数字→半角数字）；
2. 空白折叠为单个空格并去掉首尾空白；
3. 小写化。

姓名与标题再做 `squash`：去掉归一化后所有非单词字符（含标点、空格、下划线）。因此 `Smith, J.` 与 `smith j` 的姓比较结果相同，`Soil Respiration: A Review.` 与 `soil respiration a review` 视为同一标题串。

姓名比较 `_author_matches` 在 squash 后做**双向前缀**判断：完全相等，或一方以另一方开头即算匹配。这能吸收“李”与“李明”、“Smith”与“Smithsonian”这类截断，也会带来同名误配（见 §7）。中文叙述引用中的姓名会先裁掉“由/在/见/据/与/和/及/对/从”等引导字及“等/等人”后缀，再尝试裁到文献表中已知的姓。

## 4. 引用识别

识别四类形态：

- **顺序编码**：`[1]`、`[1,3]`、`[3-6]`、`[1-4,6-10]`，半角方括号与全角方括号都接受。逗号、顿号分隔逐项解析；`-`、`–`、`—`、`~` 连接的数字对在跨度 ≤ 200 时展开为连续编号，否则只保留端点。重复编号去重并保留首次顺序。
- **中文叙述式**：2–4 个连续汉字（可带“等/等人”）后接 `（年份）`，例如 `张三等（2021）`。
- **英文叙述式**：大写开头的姓名，可带 `et al.`、`and Name` 或 `& Name`，后接 `(年份)`，例如 `Smith et al. (2019)`。
- **括号式**：圆括号或全角括号内的片段，按 `;`/`；` 分成多段；每段须含 1900–2099 的年份，或含 `等`、`et al.`、`&`、`and` 之一；作者按 2–4 汉字或大写英文词抽取，排除 `et/al/and/the/of/in/on/for/with/eds/ed/by`；抽到 0 个或超过 12 个作者则放弃该段。

`等` 与 `et al.` 在解析时统一替换为分隔符，只保留第一作者参与匹配。年份可带小写字母后缀（如 `2020a`），比较时只用数字部分。URL 开头或纯数字/标点的括号内容不当作引用。同一括号已被叙述式正则占用时，括号式扫描不重复计入。

## 5. 规则

严重级别在代码中固定，不由上下文推断。所有发现按 `(行, 列, 代码)` 排序。

### C01 正文引用在文献表中无匹配（error）

对每条**带年份**的著者-年份引用，逐条文献比较：年份必须相等，且引用中任一姓名与文献中任一姓匹配；全部不匹配即报告。引用可以匹配到同名同年的不同文献，只要有一条满足就算解决。缺年份的引用不走 C01，由 C10 处理。

### C02 文献条目从未被引用（error）

对每条文献：若其编号出现在任一顺序编码引用中，或存在某条著者-年份引用与该文献年份相同、且任一姓名与文献姓匹配，则视为已引用；否则报告。缺年份的正文引用无法证明文献被引用，因此该文献仍可能同时触发 C02（与 C10 并存）。

### C03 重复条目（error）

两两比较文献条目。满足任一条件即报告后一条：

- 两条都有 DOI，且 NFKC + 小写后的 DOI 完全相同；
- 两条标题 squash 后长度都 ≥ 8，且 `difflib.SequenceMatcher` 比值 ≥ 0.90。

每条后位条目最多报告一次（遇到第一个重复即 `break`）。短于 8 个字符的标题（squash 后）不做相似度判断，但仍做 DOI 判断。相似度是字符级比值，不做分词或语义判断。

### C04 编号问题（error）

三类独立检查：

1. **越界**：任一顺序编码引用中的编号不在文献编号集合内，逐个编号报告；
2. **断档**：文献编号排序后，相邻编号差 > 1 时，在较大编号条目所在行报告缺失编号；
3. **首次出现顺序**：按正文顺序扫描编号引用，维护已见编号集合与历史最大编号；新编号的最小值小于历史最大值时报告，且同一行只报告一次。之后把本组编号并入已见集合并更新最大值。

### C05 文献条目缺年份（error）

文献条目中抽取不到 1900–2099 的年份即报告。抽取前会先删除 DOI、doi.org URL 和普通 URL，避免把 DOI 中的数字当年份。1899 年及更早的文献会被误判为缺年份。

### C06 混用引用制（warning）

同一稿件同时存在顺序编码引用与著者-年份引用时报告一条，位置取两种风格各自首次出现行中的较晚者。

### C07 DOI 格式非法（error）

只在文献条目内扫描。候选串以 `10.` 开头，截到空白或 `, ， ; ； 。` 为止，去掉尾部 `.,;:，；。、)` 和 `doi:`/`DOI:`（含全角冒号）前缀。候选必须整体匹配 `10\.\d{4,9}/\S+`，且不能以 `/` 结尾；否则报告。`https://doi.org/...` 与 `http(s)://dx.doi.org/...` 也解析，剩余部分不合法时报告。校验仅限正则，不解析 DOI 句柄，也不验证注册机构是否存在。

### C08 引用所在部分无参考文献区（error）

按一级标题分块。对每个不同于文献区所在块的块，报告其中第一条引用。没有文献区时，每个含引用的块各报告一条（通常就是一条）。

### C09 单处引用过长（warning）

顺序编码引用按展开后的编号个数计，著者-年份引用按作者个数计；超过 8 即报告（9 个及以上）。8 个不报。

### C10 著者-年份引用缺年份（warning）

著者-年份引用没有年份即报告。它不阻止 C01/C02 的判定。

## 6. renumber 算法

`renumber` 只处理顺序编码：

1. 解析文档；没有文献区或文献表没有数字编号标记时抛错，CLI 以退出码 2 结束并提示。
2. 按正文阅读顺序收集编号引用中**能在文献表中找到**的编号，去重得到旧编号序列；再把文献表中未被引用到的编号按列表原顺序追加，保证没有条目丢失。
3. 建立旧编号→新编号映射（新编号从 1 连续递增），并据此重排条目对象。
4. 逐行重写文献区之外的编号引用：展开本组编号，映射并丢弃映射不到的编号，升序去重，再压缩——连续 ≥ 3 个写成 `a-b`，恰好 2 个写成 `a,b`，单个写原数，组内用逗号连接。整组都映射不到时删除该引用标记。发生改写的行把连续空格/制表符合并为一个空格。
5. 重建文献区：保留原标题行，每条按 `[新编号] 原条目文本` 输出，条目之间空一行；原文献区之后的内容原样接回，文件以单个换行结束。

性质与副作用：

- 重排是确定性的，同一输入总得到同一输出；
- 条目内容（作者、标题、刊名、卷页、DOI）不改，只改编号与顺序；
- 著者-年份引用完全不动；
- 多行条目会被压成单行；
- 只出现在正文而不存在于文献表的编号（例如越界的 `[13]`）在重写时被静默删除，不会补文献；
- 映射按“首次出现”而非语义分组，因此同一段并列引用重排后仍保持相邻，但组内数字可能被压缩；
- 已按顺序编码的稿件再跑一次是幂等的。

## 7. 误报边界

以下情况有意**不报告**或采用保守判据：

- 文献区标题必须独占一行且完全匹配，`参考文献（续）` 不被识别；
- 围栏代码块内的方括号不扫描；
- 括号式引用要求年份或多作者标记，普通括注（如“（见图 2）”）通常跳过；
- 纯数字/标点括号、URL 括号不当作引用；
- 括号内作者超过 12 个时放弃该段；
- 标题短于 8 字符不做相似度去重；
- 单处引用恰好 8 篇不报 C09；
- C03 每条条目最多报一次，避免重复刷屏。

仍可能**误报**的情况：

- 正文中表示区间、矩阵、版本号的方括号数字（如 `[1,2]` 作为数学下标）会被当作引用；
- 形如“（张三，2020）”的普通括注其实就是引用，但形如“（试验，2020）”的普通括注也会被当成作者；
- 姓名双向前缀匹配会把 `李`/`李明`、`Smith`/`Smithson` 当作同一人，同名同年的不同作者也会互相“解决”C01/C02；
- 机构作者、复姓、罗马化姓名可能被错误切分；
- 无编号文献表若条目之间没有空行会被合并，引发连锁误报；
- 纯文本行“参考文献”即使只是正文里的一句话，也会开启文献区；
- 任何以 `10.` 开头的正文串都可能被当 DOI 候选。

## 8. 局限

- **格式**：只接受 UTF-8 的 Markdown/TXT；PDF、DOCX、LaTeX、知网导出文件需先转文本。
- **语义**：不核对文献真实性、作者顺序、刊名、卷期页；不做“张三”与“Zhang”的转写匹配；不处理“同上”“同前”“见前文”。
- **标准**：不实现 GB/T 7714—2015、ISO 690 或 APA 的完整著录规则；C06 只提示混用，不判断该用哪一种。
- **DOI**：只做正则形状检查，不联网解析，不检查校验位；`10.12345` 这类缺后缀的串会被判坏，而形状正确但实际不存在的 DOI 会通过。
- **编号**：不检查同一编号被两个条目重复使用；C04 只看集合与顺序，不看编号是否从 1 开始（首个编号为 3 且无更小引用时不会报）。
- **年份**：只认 1900–2099；古籍、历史文献会被当成缺年份。
- **规模**：C03 是条目两两比较，复杂度 O(n²)，数百条以内可接受，超大文献表会变慢。
- **重排**：不支持著者-年份制；会删除文献表中不存在的编号标记；会压平多行条目；不更新“第 13 篇文献”这类文字表述。
- **编码**：非 UTF-8 直接报错退出，不尝试 GBK 猜测。

## 10. 出处与参考

- GB/T 7714—2015《信息与文献 参考文献著录规则》（顺序编码制与著者-出版年制的术语背景）。
- ISO 690:2021 *Information and documentation — Guidelines for bibliographic references and citations to information resources*。
- American Psychological Association. *Publication Manual of the APA*, 7th ed., 2020（著者-年份形态参考）。
- Unicode Consortium. *Unicode Standard Annex #15: Unicode Normalization Forms*（NFKC）。
- International DOI Foundation. *DOI Handbook*（DOI 前缀 `10.` 与注册机构号长度 4–9 位）。
- Python Software Foundation. `difflib.SequenceMatcher` 文档；算法源自 Ratcliff, J. W. & Metzener, D. E. (1988). Pattern matching: The gestalt approach. *Dr. Dobb's Journal*, 13(7), 46.
